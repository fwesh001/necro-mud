# CRT Costume UI & Wave 3 Integration — Requirements

## Overview
This specification defines the interactive 1980s CRT hardware costume, procedural WebAudio oscilloscope, BIOS Defect Patcher & Spellbook modal, property-based testing invariants, and Vercel + Render deployment readiness for `@necro-mud/client`.

---

## REQ-UI-001: Interactive Phosphor Modes & Hardware Switches
WHEN a user clicks a hardware bezel control (`PHOSPHOR`, `DEGAUSS`, `SCAN`, `SFX`, `HUM`, `HUD`, `PWR`) on `CrtBezel`
THE SYSTEM SHALL update the CRT shader state (`green`, `amber`, `blood`, or `vga`; scanline intensity `high`, `low`, or `off`; audio mute/60Hz hum; cathode collapse/warm-up animation)
AND synchronize the active XTerm.js theme palette and oscilloscope beam color immediately.

## REQ-UI-002: Live WebAudio Oscilloscope
WHEN `RetroSoundEngine` initializes audio output
THE SYSTEM SHALL route all synthesized waveforms (modem handshake, mechanical keystrokes, degauss coil discharge, 8-bit event SFX, and 60Hz hum) through an `AnalyserNode`
AND `PhosphorOscilloscope` SHALL plot real-time time-domain samples on canvas, falling back to a 60Hz cathode standby ripple when idle or muted.

## REQ-UI-003: Haunted BIOS Defect Patcher & Commit Spellbook Modal
WHEN a user opens `PatchModal` from `TacticalHud`
THE SYSTEM SHALL display parsed `SCAN ANALYSIS` defect diagnostics (origin, tier, vitals, GitHub labels, source link, description, and artifact snippet)
AND allow triggering `SCAN <target>`, `PATCH <target>`, and `CAST <hotfix|refactor|rollback>` with live scroll inventory awareness.

## REQ-UI-004: Wave 3+ Backend Event Telemetry
WHEN the client receives `ServerEventPacket` events (`welcome`, `room-description`, `combat-result` with `ATTACK` or `patchResult`, `scan-result`, `narration` with `spellResult`, `status-view`, `repo-loaded`, `leaderboard-view`)
THE SYSTEM SHALL update `TacticalHud` vitals (HP, XP, title, bugs squashed, commit scrolls, active monsters, mounted repository room/monster counts)
AND trigger matching procedural audio cues without altering the 80×24 ANSI terminal stream.

## REQ-UI-005: Cold-Start Deployment Readiness
WHEN the application initializes in production (`Vercel + Render`)
THE SYSTEM SHALL resolve the WebSocket endpoint from `process.env.NEXT_PUBLIC_WS_URL` (falling back to `ws://localhost:4000`),
derive the corresponding HTTP(S) `/api/health` URL,
AND fire a non-blocking wake-up ping during `BootSequence` while displaying remote carrier lock status.

## REQ-UI-006: Property-Based Terminal & HUD Invariants
FOR ALL randomized inputs generated by `fast-check` across 1,000+ iterations
THE SYSTEM SHALL guarantee `stripAnsi` idempotence, `wrapTerminalText(..., 80)` visible line length `<= 80`, bounded `[0, 100]` HP percentages and `[0, totalSegments]` LED segment counts, and exception-free HUD parsing.


### REQ-UI-007: Auto-Scaling 80-Column CRT Grid & Phosphor Scrollbars
- **Component**: `Terminal.tsx`, `globals.css`
- **Behavior**: Lock `xterm.js` column geometry to `cols: 80` while dynamically scaling `fontSize` (clamped `9px–22px`) and proportional `rows` (`24–48`) via `ResizeObserver` so CP437 80-column ASCII artwork fills the glass monitor horizontally without dead black right-margin space or line wrapping. Hide native white OS scrollbars and scrollbar arrow buttons (`::-webkit-scrollbar-button`), replacing `.xterm-viewport` and `.crt-scroll` overflow chrome with an ultra-thin `3px` phosphor thumb (`var(--crt-accent)`).

### REQ-UI-008: Active Objective Guidance & Context-Aware Macro Keycaps
- **Component**: `telemetry.ts`, `TacticalHud.tsx`, `page.tsx`
- **Behavior**: Parse unlocked `Exits:` directions from ANSI `room-description` packets and compute a 4-step `Active Objective` tracker (`STEP 1/4` through `STEP 4/4`). Highlight valid movement exits with glowing phosphor dots, highlight step-relevant actions, and dim unavailable actions (`MOVE` toward blocked exits, combat macros with `0` active monsters, `CAST` with empty inventory). Intercept clicks on dimmed keys locally with an error audio cue and an inline **Tactical Advisory** banner without sending doomed commands over WebSocket.

### REQ-UI-009: Necromancer's Field Guide & Preset Repository Chips
- **Component**: `FieldGuideModal.tsx`, `CrtBezel.tsx`, `TacticalHud.tsx`
- **Behavior**: Provide a 3-tab modal (`[? GUIDE]`) accessible from both the CRT monitor bezel and Telemetry Deck header explaining the 30-second quickstart loop, tactical buttons/edge-case recovery, and CRT hardware/WebAudio controls (`Escape` to dismiss). Add one-click preset repository chips (`fwesh001/necro-mud`, `facebook/react`, `vercel/next.js`) above the `Mounted Repo` input.

### REQ-UI-010: Live GitHub Startup Dungeon & Multi-Provider AI DM
- **Component**: `server/src/index.ts`, `server/src/engine/github-parser.ts`, `server/src/engine/ai-dm.ts`, `server/src/ws/handler.ts`
- **Behavior**: Seed the mock dungeon for instant healthcheck startup while asynchronously hydrating live `fwesh001/necro-mud` rooms and issues on boot (synchronizing early WebSocket connections up to `2500ms` or hot-swapping `repo-loaded` once ready). Auto-detect Groq (`gsk_`), xAI Grok (`xai-`), Gemini (`AIza`), and OpenAI API keys across `LLM_API_KEY`, `GROQ_API_KEY`, `XAI_API_KEY`, `GROK_API_KEY`, `kiro_llm_api`, `OPENAI_API_KEY`, and `GEMINI_API_KEY`, formatting responses to `<= 80` columns with deterministic fallback on timeout or error.
